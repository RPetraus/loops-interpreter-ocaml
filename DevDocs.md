My implementation is complete and all features of the Loops language have been implemented soundly. It uses an exception called EvalError alongside descriptive messages to notify the user of errors in their Loops program. Additionally, it implements comments and all necessary statements and expressions, accounting for the scoping specifications of blocks under different circumstances.

In the root directory I have:
- _build folder: Consists of files generated by Dune to compile my code
- src folder: Contains my source code files
- test folder: Contains my test files
- .gitignore file: Set for git to ignore _build folder
- DevDocs.md file: Developer Documentation
- dune-project file: Configures the Dune build system
- README.md file: Provides broad specifications of the project

In my src folder I have:
- ast.ml: Defines types for the Abstract Syntax Tree representing Loops programs
- dune: Configures how dune should use files to compile
- eval.ml: Handles the evaluation of Loop program files represented as strings
- lexer.mll: Defines the lexicon that tokenizes input
- main.ml: Reads Loops programs from files, parsing and evaluating said program, and printing output
- parser.mly: Defines the precedence, associativity, and grammar of the Loops language

I found it interesting how we're using an existing programming language to create a new one. It makes me wonder how the first language was developed. I also wonder whether a similar pattern follows below functional programming languages where more basic languages are used to define functional programming languages.
